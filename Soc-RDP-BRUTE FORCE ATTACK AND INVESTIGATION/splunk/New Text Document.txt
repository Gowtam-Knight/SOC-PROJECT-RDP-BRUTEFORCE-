## Splunk SOC Dashboard — Windows Security Monitoring

This dashboard was developed to monitor Windows security telemetry using **Splunk**, with **Windows Security Event Logs** and **Sysmon** forwarded from the Windows endpoint.

The dashboard focuses on authentication monitoring, RDP activity, privilege usage, credential access, account enumeration, and process/network activity.

---

## 7. Failed RDP Authentication Events

### SPL

```spl
index=soc-windows EventCode=4625 Logon_Type=10
| table _time Account_Name Source_Network_Address ComputerName Logon_Type Failure_Reason
| sort - _time
```

### Visualization

**Table**

**Title:** `Failed RDP Authentication Events`

### Purpose

Displays individual failed RDP authentication attempts. Analysts can investigate:

* Attempted account
* Source IP address
* Target computer
* Logon type
* Failure reason
* Timestamp

This panel is useful for identifying repeated authentication failures and potential RDP brute-force activity.

## 9. Failed vs Successful RDP Authentication

### SPL

```spl
index=soc-windows (EventCode=4624 OR EventCode=4625) Logon_Type=10
| stats
    count(eval(EventCode=4625)) as Failed
    count(eval(EventCode=4624)) as Successful
```

### Visualization

**Column Chart**

**Title:** `RDP Authentication Results`

### Purpose

Provides a direct comparison between failed and successful RDP authentication attempts.

Example:

```text
Failed       █████████████
Successful   █████
```

This provides a quick overview of the authentication activity occurring on the monitored endpoint.

**Bar Chart**

## 16. Successful Logon Type Distribution

### SPL

```spl
index=soc-windows EventCode=4624
| stats count by Logon_Type
| sort - count
```

### Visualization

**Column Chart**

**Title:** `Successful Logon Types`

### Purpose

Shows the distribution of successful Windows logon types.

This is important because **Event ID 4624 does not automatically mean RDP**. RDP sessions specifically use **Logon Type 10**.

The panel helps distinguish RDP authentication from other Windows authentication methods.

## Detection Scenario

### RDP Brute-Force Investigation

A typical investigation can follow this sequence:

```text
1. Multiple failed RDP logins
             ↓
2. Identify source IP
             ↓
3. Identify targeted account
             ↓
4. Check for successful RDP login
             ↓
5. Investigate privileged logon activity
             ↓
6. Review explicit credential usage
             ↓
7. Check account/group enumeration
             ↓
8. Review Sysmon process creation
             ↓
9. Review network connections
             ↓
10. Build incident timeline
```

This demonstrates a practical **SOC analyst workflow** using authentication, endpoint, and network telemetry rather than relying on a single event.
